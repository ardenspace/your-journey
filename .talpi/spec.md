# Spec: 당신의 여정 (Your Journey) — v1 로컬 MVP

## Product Picture

단 한 사람을 위한 일기장. 치료처럼 보이지 않는 치유.

- **누구를 위해**: 첫 사용자이자 기준 사용자는 Arden의 어머니 — 중년 여성, 네이버 블로그와 종이 수첩으로 이미 기록 습관이 있음. 자기 연민이 깊지만 병원·상담소는 "남한테 어떻게 말하냐"며 거부. 이 앱은 상담사가 아니라 다정한 일기장인 척하며, 스며들듯 과거를 꺼내게 만들어 회고와 케어를 전달한다. 기기는 Android 폰 + Android 태블릿 — 단, v1은 오프라인 전용이므로 **한 기기(폰)에서 쓰는 것이 기준**이고, 두 기기에 각각 설치하면 데이터가 분리된다(병합은 Phase 2 동기화). 이후 Play Store 정식 출시로 다른 중년 여성 사용자까지 확장.
- **핵심 경험 (반드시 맞아야 하는 순간)**: 홈에 뜬 오늘의 질문 하나를 보고, 종이 일기장처럼 꾸민 화면에 마음 가는 대로 쓰고 "간직하기"를 누르는 순간. 압박도, 분석도, 지켜본다는 느낌도 없어야 한다.
- **스모크 시나리오 ("된다"의 정의)**: 앱을 열면 홈에 여정 경로와 오늘의 질문이 보인다 → "이 이야기 써 볼까요?"로 쓰기 화면에 들어가 속지·배경·글자 크기를 고르고 일기를 쓴다 → "간직하기"로 저장 → 목록에서 방금 쓴 일기가 보이고, 여정 경로에 걸음이 반영된다. 네트워크 없이 전 과정이 동작한다.

### 핵심 원칙 (모든 기능의 판단 기준)

1. **앱은 일기를 읽었다는 티를 내지 않는다.** 위로는 구조에서 오지, 반응에서 오지 않는다. 일기 내용을 분석·반영하는 기능은 만들지 않는다.
2. **통제권은 언제나 쓰는 사람에게.** 질문은 끌 수 있고, 봉인은 본인이 정하고, 강요되는 것은 없다.
3. **스며들듯 깊어진다.** 질문은 가벼운 오늘에서 시작해 장(章) 단위로 어린 시절 → 젊은 날 → 후회와 화해로 서서히 나아간다. 진행은 순서 기반이며 일기 내용에 따라 분기하지 않는다.

## Requirements

각 항목은 독립적으로 검증 가능하다.

1. **일기 쓰기**: 자유 쓰기가 기본. 제목은 선택, 본문은 필수(빈 본문은 저장되지 않는다 — 공백·개행만 있는 본문도 빈 것으로 친다). 하루에 몇 편이든 쓸 수 있다. 꾸미기 — 속지(무지/줄노트/모눈), 글자 크기(작게 18/보통 20/크게 24), 배경색 4종(값은 Conventions의 팔레트). 마지막 사용한 꾸미기 설정이 다음 일기의 기본값이 되고(저장 완료 시에만 갱신), 첫 일기의 기본값은 Conventions의 기본 스타일이다.
2. **오늘의 질문**: 하루에 1개만 제시된다. 답해도 되고, 무시하고 다른 이야기를 써도 되고, 설정에서 질문 모드를 끄면 카드 자체가 사라진다. 답하지 않은 질문은 **실제로 카드가 표시된 날 수 기준 최대 3일** 유지된 뒤 조용히 다음 질문으로 넘어간다 — 앱을 열지 않았거나 질문 모드를 꺼 둔 날은 세지 않는다. 질문에서 시작해 쓴 일기는 그 질문과 연결되어 저장된다(쓰기 화면에 진입한 시점의 질문 기준 — 쓰는 도중 자정이 지나도 그대로). 질문에 답한 날에도 카드는 그날 하루 그대로 표시된다. 질문 뱅크가 소진되면 질문 카드는 표시되지 않는다.
3. **타임캡슐**: 봉인은 일기를 저장하는 시점에만 선택할 수 있다(이미 저장된 일기를 나중에 봉인하는 것은 v1 범위 밖). 개봉일은 프리셋(한 달/세 달/여섯 달/일 년 뒤) 또는 **캘린더 UI에서 직접 선택**할 수 있으며, 캘린더 선택은 내일(로컬 기준, 내일 포함) 이후 날짜만 허용되고 상한은 두지 않는다(얼마나 먼 미래든 본인이 정한다 — 원칙 2). 일기를 봉인하면 개봉일까지 본인도 내용을 볼 수 없다. 봉인 중에는 목록·열람 어디에서도 **작성일과 봉인 상태(개봉 예정일)만 표시되고 제목·본문은 표시되지 않는다.** 개봉일이 되면 로컬 알림이 오고, 열람 화면에서 "열어보기"를 눌러야 개봉된다(개봉은 명시적 행위). 개봉 후에는 일반 일기처럼 보이며, 한 번 개봉한 일기는 다시 봉인할 수 없다.
4. **여정 시각화**: 홈에서 기록이 쌓일수록 이어지는 경로 메타포. 기록 수는 저장된 일기 개수이며 봉인된 일기도 포함한다(쓴 행위 자체가 걸음이므로). 숫자·통계·잔소리 텍스트는 일절 노출되지 않는다(테스트로 강제).
5. **오프라인 우선**: 모든 데이터는 로컬 SQLite에 저장된다. v1에는 네트워크 호출이 하나도 없다.
6. **설정**: 질문 모드 on/off 토글. 기본값 on.
7. **태블릿 대응**: 본문 컨테이너 최대 폭 720 중앙 정렬로 폰·태블릿 모두에서 자연스럽다.
8. **일기 수정·삭제**: 일반 일기와 개봉된 일기는 열람 화면에서 수정·삭제할 수 있다. 수정은 제목·본문·꾸미기를 바꿀 수 있고 작성일과 질문 연결(`question_id`)은 유지된다(목록 정렬은 작성일 기준). 수정 저장에도 빈 본문 금지·`last_style` 갱신 규칙이 동일하게 적용된다. 봉인 중인 일기는 내용을 볼 수 없으므로 수정할 수 없지만, **삭제는 봉인 중에도 가능하다**(원칙 2 — 통제권은 쓰는 사람에게). 삭제 전에는 부드러운 존댓말로 한 번 확인하며, 삭제 시 연결된 캡슐과 예약된 알림도 함께 제거된다. 삭제는 소프트 삭제(B1)지만 사용자에게는 완전 삭제와 동일하게 보인다 — 내용은 즉시 지워지고 어디에도 다시 나타나지 않는다. 삭제해도 질문 진행 상태는 되돌리지 않는다(질문은 앞으로만 나아간다 — 원칙 3). 삭제된 일기는 여정 기록 수에서 빠지며, 이로 인해 마일스톤이 되돌아가는 것은 자연스러운 동작으로 허용한다.

### 하지 않는 것 (영구 — 원칙에 의한 금지)

- LLM 기반 답장·질문 생성 (원칙 1 위반이므로 비용과 무관하게 금지)
- 일기 내용 분석 일체 (감정 분석, 키워드 추출, 내용 기반 분기)
- 가족 공유·연결 — 이 일기장은 온전히 쓰는 사람만의 공간

## Out of Scope (v1)

- 서버 동기화·백업 (AWS 서버리스, Phase 2)
- 계정·인증 (Cognito, Phase 2)
- 이미지 첨부 (S3, Phase 2)
- Play Store 출시 준비 (Phase 3)
- App Store 출시 준비 (Apple 개발자 계정 $99/년 — 결제·심사 준비는 출시 시점에. iOS 앱 자체는 v1 지원 범위)
- 글꼴 선택·글자색 선택 UI — v1은 시스템 폰트·기본 글자색 고정 (스키마 컬럼은 기본값으로 채워 이후 확장 대비)

## Simplicity Zones

의도적으로 단순하게 유지할 것을 명시적으로 허가하는 영역:

- **인증 없음**: v1은 단일 사용자 로컬 앱. 계정·잠금 없음.
- **설정 저장**: key-value 테이블에 JSON 문자열로. 전용 컬럼·ORM 불필요.
- **마이그레이션**: 정식 마이그레이션 프레임워크 없이 멱등한 `CREATE TABLE IF NOT EXISTS` 문 배열로 충분.
- **트랜잭션 없음**: 봉인 저장(일기+캡슐 순차 쓰기)에서 캡슐 쓰기가 실패하면 일기는 일반 일기로 남는다 — 허용되는 동작. 삭제도 순차 처리(B3의 순서)이며 부분 실패로 남은 캡슐 행은 다음 삭제 시도에서 정리되면 충분하다.
- **질문 진행**: 순서 기반 커서 하나. 개인화·가중치·랜덤 없음 (원칙 3이기도 함).
- **여정 시각화**: 마일스톤 점 + 채움 정도의 단순한 렌더링이면 충분. 애니메이션·일러스트는 나중에.
- **글꼴**: v1은 시스템 폰트만. 커스텀 폰트 로딩 없음.

## Boundary Contracts

### B1: 로컬 SQLite 스키마 (저장 데이터의 형태)

Phase 2 동기화가 이 데이터를 서버로 올려야 하므로 스키마는 경계다. 테이블 3개:

- `diaries(id TEXT PK, title TEXT NULL, content TEXT NOT NULL, question_id TEXT NULL, background_color TEXT, notebook_design TEXT('plain'|'lined'|'grid'), font_family TEXT, font_size INTEGER, font_color TEXT, created_at TEXT, updated_at TEXT, deleted_at TEXT NULL)` — `background_color`·`font_color`는 hex 문자열(`#RRGGBB`), `font_family`는 v1에서 `'system'` 고정. **삭제는 소프트 삭제**: `title`·`content`를 즉시 빈 값으로 덮어쓰고(프라이버시) `deleted_at`을 기록한다. 모든 조회·기록 수 집계는 `deleted_at IS NULL`인 행만 본다 — 톰스톤은 Phase 2 동기화가 삭제를 전파하기 위한 것.
- `capsules(id TEXT PK, diary_id TEXT REFERENCES diaries, open_date TEXT, opened_at TEXT NULL, notification_id TEXT NULL, created_at TEXT)` — `notification_id`는 기기 로컬 OS 핸들이며 Phase 2 동기화 대상에서 제외한다.
- `settings(key TEXT PK, value TEXT)` — 정의된 키와 값 형태:
  - `question_mode`: `'on' | 'off'`, 기본 on
  - `question_state`: JSON `{ cursor: number, shownDate: string("YYYY-MM-DD") | null, shownCount: number, answeredCurrent: boolean }`
  - `last_style`: JSON `{ backgroundColor: string(hex), notebookDesign: 'plain'|'lined'|'grid', fontFamily: string, fontSize: number, fontColor: string(hex) }`

시각 표기: 시각(instant)은 UTC 기준 ISO 8601 문자열(`toISOString()` 형태)로 저장하고, "오늘" 판정과 개봉 시각(오전 9시) 계산은 기기 로컬 타임존으로 한다. id는 UUID.

**개인 데이터 보호**: 일기 본문은 이 DB 밖으로 나가지 않는다 — v1에서 유일한 영속 저장소. 이 약속이 OS 레벨에서도 지켜지도록 **Android Auto Backup을 비활성화한다(`android:allowBackup=false`)** — 일기가 Google 클라우드로 자동 업로드되지 않는다. Android 12+의 기기 간 전송도 막도록 `dataExtractionRules`에서 동일하게 제외한다. (백업 부재의 대가는 Phase 2 동기화가 해소.)

`question_state`·`last_style` JSON이 손상되어 파싱할 수 없으면 조용히 기본값으로 리셋한다(사용자에게 에러를 보이지 않는다).

**iOS**: 같은 약속의 iOS 버전 — SQLite DB 파일(및 그 디렉터리)을 iCloud/기기 백업에서 제외한다(`NSURLIsExcludedFromBackupKey` 상당). 일기가 Apple 클라우드로도 나가지 않는다. 제외가 실제로 적용됐는지 검증 가능해야 한다.

### B2: DB 접근 인터페이스 (하드닝된 내부 계약)

앱(expo-sqlite)과 테스트(better-sqlite3 in-memory)라는 두 구현이 독립적으로 진화하는 seam이므로 계약으로 고정한다:

```ts
interface DB {
  run(sql: string, params?: unknown[]): Promise<void>;
  all<T>(sql: string, params?: unknown[]): Promise<T[]>;
  get<T>(sql: string, params?: unknown[]): Promise<T | null>;
}
```

도메인·레포지토리 코드는 이 인터페이스만 알고, expo-sqlite를 직접 import하지 않는다. 계약 드리프트를 막기 위해 스키마·레포지토리 테스트 스위트는 테스트 어댑터(better-sqlite3) 위에서 돌며, 두 어댑터는 같은 인터페이스 시그니처를 구현한다.

### B3: 로컬 알림 페이로드 (OS 경계)

expo-notifications로 캡슐 개봉일에 예약. OS로 나가는 것:

- 제목 `"당신의 여정"`, 본문 `"봉인해 두신 이야기가 열렸어요. 그날의 마음을 다시 만나 보세요."` — **일기 내용·제목 인용 금지 (원칙 1). 알림에 개인 데이터가 실리지 않는다.**
- data: `{ diaryId: string, type: 'capsule' }` — 탭하면 해당 일기의 열람 화면으로 이동하며, 개봉은 화면 안의 "열어보기" 버튼으로만 일어난다(탭 자체가 개봉하지 않는다).
- Android notification channel: id `capsule`, 이름 "타임캡슐", 중요도 HIGH. 앱이 포그라운드일 때도 배너로 표시한다.
- 취소: 봉인된 일기를 삭제하면 캡슐에 저장된 `notification_id`로 예약 알림을 취소한다(`notification_id`가 NULL이면 — 권한 거부로 예약이 없던 경우 — 취소를 건너뛴다). 삭제 순서는 알림 취소 → 캡슐 행 → 일기 행. 이미 발화되어 트레이에 남은 알림을 탭했는데 해당 일기가 없으면 조용히 홈으로 이동한다.
- 전달 정확도: 정확한 오전 9시 전달을 보장하지 않는다 — 근사 전달을 허용하고 `SCHEDULE_EXACT_ALARM` 권한은 요구하지 않는다. 기기 재부팅 등으로 알림이 유실되어도 개봉은 알림에 의존하지 않으므로 목록에서 그대로 열 수 있다(재예약 보정은 v1 범위 밖).
- 권한 거부 시: 알림 없이 봉인은 그대로 진행된다 (봉인이 알림에 의존하지 않는다).

### B4: 질문 뱅크 콘텐츠 형식 (사람이 소유하는 콘텐츠 경계)

질문은 LLM 없이 사람이 직접 설계·소유한다 — "엄마를 아는 사람이 설계한 질문 여정"이 차별점. 코드가 읽는 형식:

```ts
interface Question { id: string; chapter: number; order: number; text: string }
```

- id 규칙 `ch<장>-q<번호>` (예: `ch1-q1`). 배열 순서 = 제시 순서이며, `chapter`/`order` 필드와 배열 순서의 일치는 뱅크 유효성 테스트로 강제한다.
- v1은 1장(가벼운 오늘) 10개로 시작. 문구 톤: 부드러운 존댓말, 답을 강요하지 않는 열린 질문.
- 일기에는 `question_id`만 저장되므로, 기존에 배포된 질문의 id는 바꾸지 않는다(문구 수정은 가능). 장 추가는 배열 끝에 이어 붙인다.

### B5: 도메인 규칙 계약 (하드닝된 내부 계약)

UI·DB와 무관한 순수 함수로 분리하고 유닛 테스트로 고정하는 규칙:

- **질문 진행**: 같은 날 재조회는 같은 결과. 새 날에 — 직전 질문에 답했거나 표시일 수(`shownCount`)가 3에 도달했으면 다음 질문으로, 아니면 같은 질문을 유지하며 표시일 수만 +1. 표시일 수는 질문 카드가 실제로 표시된 날만 센다. 커서가 뱅크 범위를 벗어나면 질문 없음.
- **캡슐 규칙**: 개봉일 = 봉인 시점 + 선택 기간(프리셋) 또는 캘린더에서 선택한 날짜(내일 이후만 유효), 시각은 어느 쪽이든 로컬 오전 9시 고정. 결과 날짜가 존재하지 않으면(예: 1월 31일 + 한 달) 해당 월의 말일로 당긴다(클램프). 개봉일은 봉인 시점에 계산되어 저장되므로 이후 규칙이 바뀌어도 이미 봉인된 캡슐에는 소급되지 않는다. 개봉 가능 = 개봉일 도달 && 아직 안 열었음.
- **여정 진행도**: 기록 수(일기 개수) → 마일스톤 `[1, 3, 7, 14, 30, 60, 100, 150, 210, 280, 365]` 도달 개수와 다음 구간 진행율. 마지막 마일스톤을 넘으면 진행율은 1로 고정된다.
- 도메인 함수는 `new Date()`를 내부에서 호출하지 않고 항상 인자로 받는다.

## Reversibility Ledger

### Decided (hard to change)

- **스택**: Expo (React Native) + expo-router, TypeScript strict. 새 프로젝트로 시작 (예전 프로토타입 `space3-your-journey`는 참고만).
- **데이터 소유**: 오프라인 우선 — 로컬 SQLite가 원본(source of truth). 서버는 나중에 조용한 백업·동기화 역할만.
- **스키마 형태**: B1의 3-테이블 스키마. 시각은 UTC ISO 8601 문자열, 달력일 판정은 로컬 타임존.
- **프라이버시 모델 (v1)**: 일기는 기기 안에만, 평문 SQLite로 저장한다. 앱 잠금·DB 암호화 없음 — 기기 잠금(OS)을 신뢰 경계로 삼는다. 타임캡슐의 "본인도 못 본다"는 UI 레벨의 약속이다. Android Auto Backup은 비활성화(`allowBackup=false`).
- **질문 id 체계**: `ch<장>-q<번호>` — 일기가 `question_id`로 참조하므로 배포 후 id는 영구 계약. 문구는 수정 가능, id는 불변.
- **플랫폼**: Android + iOS 동시 지원 (2026-08-10 Arden 결정 — 구 "iOS 보류"를 해제, 어차피 양쪽 스토어 출시가 목표). 태블릿 레이아웃 처음부터 고려. v1은 단일 기기 사용 기준. 스토어 출시 준비는 양쪽 다 v1 범위 밖.
- **iOS bundleIdentifier**: `com.ardenspace.yourjourney` — Android applicationId와 동일 (2026-08-10 Arden 확정).
- **Phase 2 방향**: AWS 서버리스 (Lambda + API Gateway + DynamoDB + Cognito + S3), 무료 티어 범위 설계, 계정 생성 직후 billing alarm. 서버 저장 시 본문 암호화(E2E) 여부는 **미결** — Phase 2 스펙에서 결정한다. (v1 구현에는 등장하지 않지만 스키마·데이터 소유 결정의 배경.)
- **Android applicationId**: `com.ardenspace.yourjourney` — Play Store 출시 시 영구 고정되는 값 (2026-08-10 Arden 확정, Phase 1 에스컬레이션 해소).
- **언어**: v1은 한국어 단일 언어. 다국어(i18n)는 필요해지는 시점에 별도 결정 (Play Store 확장도 우선 한국어 사용자 대상).
- **원칙 1·2·3**: 제품의 정체성. 기능 판단이 갈리면 항상 원칙이 이긴다.
- **캡슐 개봉일 선택 방식**: 프리셋 4종 + 캘린더 직접 선택(내일 이후). 구 스펙의 "직접 입력"을 캘린더 UI로 구체화 (마이그레이션 시 확인된 스펙-플랜 불일치의 최종 정리).
- **삭제 의미론**: 소프트 삭제(톰스톤) — `deleted_at` 기록 + 내용 즉시 소거. Phase 2 동기화에서 기기의 삭제가 서버로 전파되게 하기 위한 결정 (하드 삭제 시 백업 재출현 문제, 패널 지적을 수용).

## Conventions

- **테마 토큰**: paper `#FFFDF7`, ink `#3A3A3A`, accent `#C08A5D`, subtle `#8A8578`, card `#FFFFFF`. 글자 크기 body 20 / title 24 / small 16. 터치 타겟 최소 48dp. 본문 컨테이너 maxWidth 720. 모든 화면이 이 토큰에서 가져다 쓴다.
- **일기 배경색 팔레트 4종**: `#FFFDF7`(종이), `#FDF3E7`(살구), `#EFF5EF`(연둣빛), `#EEF2F7`(하늘빛).
- **기본 스타일** (첫 일기): 배경 `#FFFDF7`, 속지 줄노트, 시스템 폰트, 글자 크기 20, 글자색 `#3A3A3A`.
- **문구 톤**: 전부 한국어, 부드러운 존댓말 ("오늘을 써 볼까요?"). 명령조·통계·잔소리 금지. 중년 사용자 기준 — **일기 본문** 글자 크기는 18 이상(보조 텍스트·캡션은 토큰 small 16 허용).
- **공유 유틸 정책**: 날짜 처리(`localDateString` 등), 질문 진행, 캡슐 규칙, 여정 진행도는 반드시 `src/domain`의 순수 함수로 — UI·DB에서 로직 중복 금지.
- **레이아웃 규칙**: 화면은 `app/`(expo-router), 로직은 `src/`(db / repositories / domain / content / ui / notifications). 도메인은 React를 import하지 않는다.
- **실패 시 사용자 경험**: 조용하고 다정하게. 기술 용어·에러 코드 노출 금지. 저장 실패처럼 사용자 행동이 필요한 경우만 부드러운 존댓말 안내 (예: "잠시 후 다시 한번 눌러 주세요"). 알림 권한 거부는 실패로 취급하지 않는다 — 기능은 조용히 축소된다.
- **커밋**: conventional commits (`feat:`, `test:`, `chore:`), 태스크마다 최소 1회.
